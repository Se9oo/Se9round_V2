실행 컨텍스트는 **실행할 코드에 제공할 환경 정보들을 모아놓은 객체**이다.  
자바스크립트 엔진은 실행 컨텍스트를 콜 스택(call stack)에 쌓아 올리며 관리하고, 가장 위에 있는 컨텍스트를 활성화해 코드를 실행한다.  
어떤 실행 컨텍스트가 활성화되는 시점에 선언된 변수를 위로 끌어올리고(hoisting), 외부 환경 정보를 구성하고, this 값을 설정하는 등의 동작을 수행한다.

## 실행 컨텍스트를 구성하는 방법

실행 컨텍스트를 구성할 수 있는 방법으로는 `전역 공간`, `eval()`, `함수` 등이 있다.  
`eval()`은 문자열을 코드로 실행할 수 있는 함수지만 보안 및 성능 문제로 현재는 거의 사용하지 않는다.

## 실행 컨텍스트에 담기는 정보

실행 컨텍스트를 구성할 때 수집하는 정보에는 `VariableEnvironment`, `LexicalEnvironment`, `ThisBinding`이 있다.

### VariableEnvironment, LexicalEnvironment

VariableEnvironment와 LexicalEnvironment는 동일한 내용으로 구성되지만, LexicalEnvironment는 함수 실행 도중 변경되는 사항이 즉시 반영되고, VariableEnvironment는 초기 상태, 즉 컨텍스트가 생성될 때의 상태를 유지한다.

VariableEnvironment와 LexicalEnvironment는 `environmentRecord`와 `outerEnvironmentReference`로 구성되어 있다.

#### environmentRecord

`environmentRecord`는 현재 컨텍스트와 관련된 코드의 아래와 같은 식별자 정보들이 저장된다.

- 매개변수의 이름
- 함수 선언
- 변수명

컨텍스트가 생성될 때, 코드를 처음부터 끝까지 쭉 훑으면서 식별자 정보를 순서대로 수집한다.  
이렇게 정보를 수집하는 과정을 [hoisting](https://se9round.dev/post/hoisting)이라 한다.

#### outerEnvironmentReference

`outerEnvironmentReference`는 해당 함수가 선언된 위치의 LexicalEnvironment 정보가 담긴다.

코드 상에서 어떤 변수에 접근하려고하면 현재 컨텍스트의 LexicalEnvironment에서 찾고,  
없다면 `outerEnvironmentReference`에 담긴 상위 컨텍스트의 LexicalEnvironment에서 해당 변수를 찾는다.  
계속 변수를 찾다가 전역 컨텍스트의 LexicalEnvironment까지 탐색해도 해당 변수를 찾지 못하면 `ReferenceError`가 발생한다.

이렇게 outerEnvironmentReference를 이용해 변수를 찾아가는 과정을 스코프 체인이라고 한다.

### ThisBinding

`ThisBinding`은 실행 컨텍스트가 활성화될 때 this가 가리킬 대상을 결정한다. 자세한 내용은 [this]()에서 다룬다.
