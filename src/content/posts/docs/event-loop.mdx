이벤트 루프는 싱글 스레드인 자바스크립트가 비동기 작업을 처리할 수 있게 해주는 메커니즘이다.  
콜 스택이 비면, 대기 중인 콜백을 큐에서 꺼내 스택에 올리는 일을 계속 반복한다.

## 블로킹과 논블로킹

- **블로킹**: 작업이 끝날 때까지 다음 코드가 실행되지 못하고 기다리는 것
- **논블로킹**: 작업을 맡겨두고 바로 다음 코드를 실행하는 것

싱글 스레드에서 오래 걸리는 작업을 블로킹으로 처리하면, 그동안 클릭도 렌더링도 전부 멈춘다.  
그래서 자바스크립트는 오래 걸리는 작업을 다른 곳에 맡기고, 끝나면 결과(콜백)를 받아 실행하는 방식을 사용한다.

## 자바스크립트 엔진과 런타임

여기서 "다른 곳"은 자바스크립트 엔진이 아니라 **런타임 환경**이다.

- **자바스크립트 엔진** (V8 등): 콜 스택과 힙을 가지고 코드를 실행한다.
- **런타임 환경** (브라우저, Node.js): 엔진에 Web API, 태스크 큐, 이벤트 루프 등을 제공한다.

엔진 자체는 싱글 스레드지만, 브라우저는 여러 스레드를 사용해 비동기 작업을 처리한다.

## 이벤트 루프를 구성하는 요소

![이벤트 루프 구조](https://hfjaydlcifnsisqntesa.supabase.co/storage/v1/object/public/se9round-images/tech/event-loop/event-loop.svg)

### 콜 스택 (Call Stack)

콜 스택은 현재 실행 중인 함수가 쌓이는 곳이다. 함수가 호출되면 스택에 올라가고, 실행이 끝나면 빠진다. 자바스크립트 엔진에는 콜 스택이 하나뿐이라서 한 번에 하나의 함수만 실행할 수 있다.

이벤트 루프 입장에서 중요한 것은 **콜 스택이 비어 있는지**다. 큐에 있는 콜백은 콜 스택이 비어야만 실행될 수 있다.

### Web API

`setTimeout`, `fetch`, DOM 이벤트처럼 시간이 걸리는 작업은 자바스크립트 엔진이 아니라 브라우저가 처리한다.

### 큐 (Queue)

비동기 작업이 끝나면 콜백이 큐에 들어가 실행 차례를 기다린다.  
큐는 **마이크로태스크 큐**와 **태스크 큐**(매크로태스크 큐라고도 부른다) 두 종류가 있다.

| 큐                | 들어가는 콜백                                                                         | 우선순위 |
| ----------------- | ------------------------------------------------------------------------------------- | -------- |
| 마이크로태스크 큐 | `Promise.then/catch/finally`, `await` 이후 코드, `queueMicrotask`, `MutationObserver` | 높음     |
| 태스크 큐         | `setTimeout`, `setInterval`, I/O, UI 이벤트                                           | 낮음     |

마이크로태스크 큐는 태스크 큐보다 **우선순위가 높다**. 콜 스택이 비면 마이크로태스크 큐를 **완전히 비운 뒤에야** 다음 태스크를 꺼낸다.  
마이크로태스크 실행 중에 새로운 마이크로태스크가 추가되면, 그것까지 전부 실행한다.

### async/await

`await`는 Promise 기반이다. `await` 뒤의 코드는 마이크로태스크로 예약된다고 보면 된다.

```typescript
async function foo() {
	console.log('A');
	await null;
	console.log('B'); // 마이크로태스크로 예약
}

console.log('start');
foo();
console.log('end');

// start
// A
// end
// B
```

`async` 함수는 첫 번째 `await`를 만나기 전까지는 **동기적으로** 실행된다. 그래서 `A`는 `end`보다 먼저 출력된다.  
`await`를 만나면 함수 실행이 일시 중단되고 호출한 쪽으로 돌아가며, 나머지 코드(`B`)는 마이크로태스크로 실행된다.

## 이벤트 루프의 동작 순서

이벤트 루프는 다음 과정을 계속 반복한다.

1. 콜 스택의 동기 코드를 모두 실행한다.
2. 콜 스택이 비면 마이크로태스크 큐를 완전히 비울 때까지 실행한다.
3. 필요하면 화면을 렌더링한다.
4. 태스크 큐에서 하나만 꺼내 실행한다.
5. 다시 2번으로 돌아간다.

### 실행 순서

```typescript
console.log('1');

setTimeout(() => console.log('2'), 0);

Promise.resolve()
	.then(() => console.log('3'))
	.then(() => console.log('4'));

queueMicrotask(() => console.log('5'));

console.log('6');
```

3. 마이크로태스크 큐가 비었으므로 다음 태스크: `2`

## 렌더링과 이벤트 루프

브라우저는 보통 1초에 60번(약 16.7ms마다) 화면을 다시 그린다. 렌더링은 태스크 사이, **마이크로태스크 큐가 빈 뒤**에만 일어날 수 있다.

### requestAnimationFrame

`requestAnimationFrame`(rAF)의 콜백은 **다음 렌더링 직전**에 실행된다.  
애니메이션을 `setTimeout`으로 구현하면 프레임과 타이밍이 어긋날 수 있지만, rAF는 렌더링 주기에 맞춰 실행되므로 애니메이션에 적합하다.

### 마이크로태스크가 화면을 멈추게 하는 이유

```typescript
// 화면이 멈춘다
function loop() {
	Promise.resolve().then(loop);
}
loop();

// 화면이 멈추지 않는다
function loop2() {
	setTimeout(loop2, 0);
}
loop2();
```

- `Promise` 버전: 마이크로태스크가 계속 새 마이크로태스크를 추가한다. 이벤트 루프는 마이크로태스크 큐를 전부 비워야 다음 단계로 가므로, 렌더링 단계에 영원히 도달하지 못한다.
- `setTimeout` 버전: 태스크는 한 번에 하나만 실행되므로, 태스크 사이사이에 렌더링과 이벤트 처리가 끼어들 수 있다.

### 긴 작업 쪼개기

콜 스택을 오래 점유하는 작업은 그동안 렌더링과 사용자 입력을 막는다.  
이럴 때 작업을 잘게 나누고, 사이사이 `setTimeout`으로 다음 태스크로 넘기면 브라우저가 중간에 렌더링과 이벤트 처리를 할 수 있다.

```typescript
function processAll(items) {
	let i = 0;

	function chunk() {
		const end = Math.min(i + 1000, items.length);
		for (; i < end; i++) {
			handle(items[i]);
		}
		if (i < items.length) {
			setTimeout(chunk, 0); // 다음 태스크로 넘김
		}
	}

	chunk();
}
```

## 정리

- 자바스크립트 엔진은 싱글 스레드지만, 런타임(브라우저)이 Web API와 이벤트 루프로 비동기를 처리한다.
- 비동기 콜백은 콜 스택이 **비었을 때만** 실행된다.
- 이벤트 루프 한 사이클: **태스크 1개 → 마이크로태스크 전부 → (필요 시) 렌더링**
- `Promise.then`, `await` 이후 코드는 마이크로태스크라서 `setTimeout`보다 먼저 실행된다.
- 마이크로태스크를 무한히 만들면 렌더링이 멈추고, 긴 동기 작업은 태스크로 쪼개야 한다.
