자바스크립트에서 `this`는 [실행 컨텍스트](https://se9round.dev/post/실행-컨텍스트)가 생성될 때 함께 결정된다.  
실행 컨텍스트는 함수를 호출할 때 생성되므로, this는 **함수를 호출할 때** 결정된다.

## 전역 공간에서의 this

전역 공간에서 this는 전역 객체를 가리킨다. 브라우저 환경에서의 전역객체는 `window`이고, Node.js 환경에서는 `global`이다.

## 메서드로서 호출할 때 그 메서드 내부에서의 this

메서드로 호출한 호출 주체가 this가 된다.

```typescript
const obj = {
	methodA: function () {
		console.log(this);
	},
	inner: {
		methodB: function () {
			console.log(this);
		},
	},
};

obj.methodA(); // {inner: {...}, methodA: f} => obj가 주체
obj.inner.methodsB(); // {methodB: f} => inner가 주체
```

## 함수로서 호출할 때 그 함수 내부에서의 this

함수로서 호출하는 것은 호출 주체를 명시하지 않고 개발자가 코드에 직접 관여해서 실행한 것이기 때문에 호출 주체를 알 수 없다.  
실행 컨텍스트가 활성화 될 때 함수로서 호출할 때 그 함수의 this는 지정되지않고, this가 지정되지 않는 경우 this는 전역 객체를 바라보기 때문에
따라서 함수로서 호출할 때의 this는 전역 객체이다.

## 콜백 함수 호출 시 그 함수 내부에서의 this

콜백함수도 기본적으로 함수이기 때문에 this는 전역 객체가 된다. 하지만 제어권을 받은 함수가 콜백 함수에 별도로 this가 될 대상을 지정하는 경우에는 그 대상이 this가 된다.

```typescript
setTimeout(function () {
	console.log(this); // 전역 객체
}, 300);

[1, 2, 3, 4, 5].forEach(function (x) {
	console.log(this, x); // 총 5회 전역객체와 각 인자 값이 출력됨
});

// addEventListener 메서드는 콜백 함수를 호출할 때 자신의 this를 상속하도록 되어있음.
// addEventListener의 this는 button element
document.body.innerHTML += '<button id="a">클릭</button>';
document.body.querySelector('#a').addEventListener('click', function (e) {
	console.log(this, e); // this -> button
});
```

## 생성자 함수 내부에서의 this

자바스크립트에서 함수는 `new` 명령어와 함께 호출하면 생성자로서 동작하게 된다.  
그리고 어떤 함수가 생성자 함수로서 호출된 경우, this는 새로 만들어질 인스턴스 자신이 된다.

```typescript
var Human = function (name, age) {
	this.name = name;
	this.age = age;
};

var 철수 = new Human('철수', 10);
var 길동 = new Human('길동', 20);

console.log(철수, 길동);
// Human { name: '철수', age: '10' }
// Human { name: '길동', age: '20' }
```

## 명시적으로 this를 바인딩하는 방법

위 규칙들을 깨고 this에 별도의 대상을 바인딩하는 방법도 있다.

### call()

`call()`은 call 메서드의 호출 주체인 함수를 즉시 실행한다.  
첫 번째 인자에는 this를 바인딩할 대상이 위치하고, 이후의 인자들은 호출할 함수의 매개변수로 사용한다.

```typescript
var func = function (a, b, c) {
	console.log(this, a, b, c);
};

func(1, 2, 3); // Window {...}, 1 2 3
func.call({ x: 1 }, 4, 5, 6); // { x: 1 } 4 5 6

var obj = {
	a: 1,
	method: function (x, y) {
		console.log(this.a, x, y);
	},
};

obj.method(2, 3); // 1 2 3
obj.method.call({ a: 5 }, 6, 7); // 5 6 7
```

### apply()

`call()`과 동일하게 동작하지만, 첫 번째 인자 이후에 오는 인자 값은 배열의 형태라는 차이점이 있다.

```typescript
var func = function (a, b, c) {
	console.log(this, a, b, c);
};

func.apply({ x: 1 }, [4, 5, 6]); // { x: 1 } 4 5 6

var obj = {
	a: 1,
	method: function (x, y) {
		console.log(this.a, x, y);
	},
};

obj.method.apply({ a: 4 }, [5, 6]); // 4 5 6
```

### bind()

`call()`과 비슷하지만, 즉시 호출하지 않고 넘겨 받은 this 및 인수들을 바탕으로 새로운 함수를 반환한다.  
새로 반환된 함수를 호출할 때 인수를 넘기면 그 인수들은 기존 bind 메서드를 호출할 때 전달했던 인수들의 뒤에 이어서 등록된다.

```typescript
var func = function (a, b, c, d) {
	console.log(this, a, b, c, d);
};
func(1, 2, 3, 4); // Window {...} 1 2 3 4

var bindFunc1 = func.bind({ x: 1 });
bindFunc1(5, 6, 7, 8); // { x: 1 } 5 6 7 8

var bindFunc2 = func.bind({ x: 1 }, 4, 5);
bindFunc2(6, 7); // { x: 1 } 4 5 6 7
bindFunc2(8, 9); // { x: 1 } 4 5 8 9
```

## 화살표 함수

화살표 함수는 실행 컨텍스트 생성 시 this를 바인딩하는 과정이 제외됐다. 이 함수 내부에는 this가 없으며,
접근하고자 하면 **스코프체인상 가장 가까운 this**에 접근한다.

```typescript
var obj = {
	outer: function () {
		console.log(this); // obj

		var innerFunc = () => {
			console.log(this); // obj
		};

		innerFunc();
	},
};
obj.outer();
```
